Ghost job detection

GhostHire

Some jobs are advertised on boards long after the company stopped hiring for them. GhostHire reads a job board and the employer's own careers page, and reports the listings that appear on one but not the other.

Every claim on this page cites the board URL, the careers-page URL, and the Bright Data collector that produced them — so it can be checked, or refuted, in about ten seconds.

02 — Coverage

Which employers we can actually check

Verifying a listing means reading that employer's own careers page. Where we can't, the reason is stated — an unreadable applicant-tracking system, a portal that builds itself in the browser, or a page that is off-limits under the public-data-only rule. A blank cell would hide which.

03 — What we won't claim

Absence of evidence is not evidence of absence

A listing is only scored when we have successfully read that company's careers page. Where we haven't, the listing carries no score at all — not zero, which would read as "we checked and it is fine". Scoring those would mean accusing employers on the strength of data we never collected.

The database enforces this rather than trusting us to remember: ghost_score IS NULL exactly when career_page_checked = 0, as a CHECK constraint.

04 — Scraper workflow

Collectors, and what broke

Each collector was built by handing Bright Data Scraper Studio a plain-English description of the fields wanted. Every row stored here carries the c_* ID of the collector that produced it.

05 — Structured output

The archive behind every number

Every collector response is written to data/snapshots/ before anything reads it, successes and failures alike. The database is a cache of this archive — delete it, run db --from-snapshots, and every number on this page comes back without a network call.

Evidence worth checking, not proof. Scoring weights are a judgement, not ground truth. Only public pages are read — nothing behind a login or paywall.
